# Input Focus（打字动画生成器）· 需求与技术方案

> 状态：v0.4 — 4 个输入框模板、镜头质感、文字出现动效已完成；剩余：系统外框 + 深浅主题、预设管理等（2026-09-28）
> 日期：2026-09-28

---

## 1. 产品概述

一个在浏览器里运行的本地网页工具：用户输入一段文案、调整参数，实时预览"输入框光标闪烁 → 打字输入"的动画，并导出为 MP4 视频。

**核心体验**：画面像一台摄像机对着屏幕拍摄——光标先闪几下，然后文字按真实的中/英文节奏被敲进输入框，镜头推近并平滑追着最后一个词走。

**典型用途**：短视频片头、产品演示、AI 类内容的"提问"镜头素材。

---

## 2. 目标与非目标

### 目标
- 打字节奏真实，中文、英文有明显不同的输出节奏
- 镜头推近特写，平滑跟随最新输入的词
- 多种输入框模板、屏幕质感效果可选
- 预览所见即导出所得（逐帧确定性渲染，导出不掉帧）
- 一键导出 MP4 (H.264)，可带跟随打字节奏的键盘音效

### 非目标（本期不做）
- 打错字再删除、标点处长停顿、结尾回车/点发送等"人味儿"细节
- 拼音输入法候选框模拟
- 多行文本 / 输入框自动换行
- 多段文案连续播放
- 透明背景、GIF、PNG 序列导出
- 自定义字体上传
- 镜头旋转、透视倾斜、手持抖动

## 3. 动画逻辑

### 3.1 时间线

```
| 起始留白 | 光标闪烁 N 次 | 打字输入 | 结尾停留 |
   0.3s       N × 1.06s     自动计算     1.5s
```

| 阶段 | 光标 | 镜头 |
|---|---|---|
| 起始留白 | 常亮 | 全景：完整输入框约占画面宽度 70% |
| 光标闪烁 | 按设置闪 N 次（亮 530ms / 灭 530ms，接近 macOS 默认） | 全景，最后一次闪烁时开始缓慢推近 |
| 打字输入 | 输入期间常亮（真实系统行为：打字时光标不闪） | 推近到特写倍率，平滑跟随最后一个词 |
| 结尾停留 | 停止输入 500ms 后恢复闪烁 | 由"结尾拉远"开关决定：关（默认）= 保持特写；开 = 缓慢拉远到能看到完整文案 |

视频总时长由文案长度和速度自动算出，界面上实时显示。

### 3.2 打字节奏模型

先把文案切分为片段，再给每个片段分配"上屏时刻"。所有随机数来自**可设定的随机种子**，同一组参数永远生成同一个结果；界面提供"换一种节奏"按钮（换种子）。

中文、英文各有两种节奏模式，分别设置：

| | 模式 A：自然节奏（默认） | 模式 B：加速 |
|---|---|---|
| 英文 | 逐字母出现，单词之间停一小段 | 逐字母出现，越打越快 |
| 中文 | 逐词出现（模拟输入法选词上屏），词之间停一小段 | 逐字出现，越打越快 |

#### 英文 A · 逐字母 + 词间停顿
- 基础间隔 = 60 / (WPM × 5) 秒，默认 WPM = 80 → 约 150ms/字符
- 每次间隔乘以对数正态随机扰动（σ ≈ 0.35），快慢不均，更像真人
- 单词之间多停一段：词间停顿 = 基础间隔 × 词间停顿系数（默认 2×，可调）

#### 中文 A · 逐词 + 词间停顿
- 用浏览器内置 `Intl.Segmenter('zh', { granularity: 'word' })` 分词，**一个词组一次性上屏**。超过 4 字的长词拆成 2~3 字一组
- 一个词组的等待时间 = 字数 × (60 / 每分钟字数) × 随机扰动（σ ≈ 0.25）
- 默认 120 字/分钟 → 两字词约 1 秒上屏一次
- 视觉效果：停顿（在"打拼音"）→ 一下蹦出一个词 → 停顿 → 再蹦出一个词

#### 英文 B / 中文 B · 加速
逐个字符出现（中文也改为逐字），从起始速度开始，**沿一条平滑曲线**加速到峰值速度。

**曲线设计**：速度不是匀速往上加的。加速度本身也是从 0 开始、平滑变大、再平滑回落到 0。起步几乎察觉不到在变快，中段明显提速，快到峰值时柔和地"收"住，没有突然起步或突然停止的顿挫感。

```
速度
峰值 ┤                    ╭──────────
     │                 ╭──╯
     │              ╭──╯
     │          ╭───╯
起始 ┤──────────╯
     └────────────────────┬──────────→ 文案进度
     0              加速段结束        100%
```

**计算方法**：设 `p` = 当前字符序号 / 总字符数，`pa` = 加速段占比

- 缓动函数用 smootherstep：`E(x) = 6x⁵ − 15x⁴ + 10x³`（它的一阶、二阶导数在两端都为 0，正是"加速度平滑起止"）
- 速度倍率 `s(p) = 峰值倍数 ^ E(p / pa)`（`p > pa` 后保持峰值）
- 在**对数空间**插值（用指数而不是线性）：人眼对速度的感知接近对数，这样每一段的"变快程度"感觉均匀
- 第 i 个字符的间隔 = 基础间隔 / s(p)

另提供一条"缓入"曲线（ease-in，一路加速直到文案结束）作为备选。

**加速模式参数**

| 参数 | 范围 | 默认 |
|---|---|---|
| 峰值倍数 | 2× ~ 15× | 6× |
| 加速段占比 | 30% ~ 100% | 70% |
| 曲线 | S 形平滑 / 缓入 | S 形平滑 |
| 节奏抖动 | 关 / 轻微 | 关（保证曲线纯净） |

**收尾**：达到峰值后一直保持峰值速度，一口气打完最后几个字，结尾不减速。

**速度很快时**：一帧内可能出现多个字符（60fps 下间隔低于 16ms），逐帧渲染时按时间计算已上屏字符数，不会丢字或卡顿。

#### 混排
- 空格、标点各算一个单独片段，按所在语言的规则处理
- 中英文混排时逐段套用各自的模式。例如"帮我写一个 Python 脚本"，中文按词组上屏，`Python` 逐字母出现
- 加速曲线的进度 `p` 按**整段文案**计算，中英文共用同一条曲线，混排时速度也是连续的

#### 整体速度
所有时间（包括闪烁、镜头、停留）统一乘以速度倍率。

### 3.3 镜头跟随

- **焦点**：最后一个上屏的词的中心点（英文为当前正在打的单词，中文为最新上屏的词组）
- **加速模式下**：字出得太快，逐词跳动的焦点会让镜头发抖。当速度超过峰值的一半时，焦点平滑过渡为"光标位置"，镜头像匀速滑行一样跟着光标走
- **构图**：水平构图 = 特写时焦点在画面中的水平位置（默认 45%，给后续文字留出空间）；垂直构图 = 输入框在画面中的高度（默认居中，竖屏可调到上三分之一）。垂直构图对全景、特写、拉远统一生效，推拉时输入框不会上下漂移
- **平滑**：镜头位置和缩放用临界阻尼弹簧追焦点，带自然的惯性和滞后，不会跳变。弹簧按固定步长预先模拟，保证预览、拖动进度条、导出三者完全一致
- **推近**：全景 → 特写的缩放过程用同一套弹簧，特写倍率可调（默认 2.2×）
- **超长文案**：文字超出输入框宽度时，输入框内文字向左滚动（单行输入框的真实行为），镜头随之稳定在输入框右侧区域
- **开场全景**（开关，默认开）：开 = 先全景再推近；关 = 第一帧就以特写倍率定位在光标上，全程固定倍率跟随
- **结尾拉远**（开关，默认关）：开启后，打字结束约 0.5s 开始缓慢拉远，直到完整输入框进入画面
- **竖屏**：全景阶段允许输入框超出画面左右两侧。此时全景以"光标所在区域"构图，不强求看到整个输入框

### 3.4 键盘音效

音效**不与屏幕上的字符逐个同步**，而是模拟一段正常速度的打字声（约 70 WPM），从开始打字一直响到最后一个字出现：

- 字母键成串敲击（每个"词" 2~7 键，键间约 0.13s，带自然快慢波动），词与词之间按一下空格键并稍作停顿（约 0.24s）
- 打字声至少持续 1.2 秒：文案很短、画面打字不足 1.2 秒时，打字声会延续到 1.2 秒；若结尾停留太短，视频会自动加长，保证声音完整
- 打字声速度固定，不随画面节奏模式（逐词 / 加速）和整体速度倍率变化，所以始终听起来像正常打字
- 使用独立的随机数序列：开关音效或换音色都不会改变画面的打字节奏

**音色**：用 Web Audio 程序化合成（噪声冲击 + 短促共振），不依赖外部音频素材，没有版权问题。每次按键在音高、音量、音色上有轻微随机差异（同样来自随机种子），避免机械重复感。

| 参数 | 选项 / 范围 | 默认 |
|---|---|---|
| 键盘音效 | 开 / 关 | 开 |
| 音色 | 机械键盘（清脆） / 薄膜键盘（柔和） / 笔记本键盘（轻薄） | 机械键盘 |
| 音量 | 0 ~ 100% | 70% |

预览时同步播放声音（可静音），导出时混入 MP4 的 AAC 音轨。

### 4.4 屏幕模拟（单选 + 强度）
| 选项 | 效果 |
|---|---|
| 无 | 干净的屏幕画面 |
| 手机翻拍 | 彩色干涉波纹（摩尔纹），波纹会随镜头移动/缩放而流动变形；隐约可见 RGB 子像素；轻微过曝、噪点和色温偏移 |
| CRT 复古 | 横向扫描线、屏幕弧面畸变、荧光辉光、荫罩 RGB 点阵、轻微闪烁 |
| LCD 像素特写 | RGB 子像素条纹网格，网格"长在屏幕上"——镜头推得越近，像素点看得越清楚 |

强度 0 ~ 100%，默认 25%。

**实现要点**
- 摩尔纹由"屏幕像素网格 × 手机传感器网格"的拍频生成。虚拟传感器频率按特写镜头调校，并混合最近的两个谐波，所以全景和特写都有波纹，推拉镜头时波纹连续变化、不会跳变；镜头平移时波纹缓慢漂移；镜头畸变让条纹呈弧形
- 像素网格、扫描线定义在屏幕坐标系中，随镜头缩放；当网格小于约 2 个输出像素时自动淡出，避免出现假摩尔纹
- 所有尺寸以 1080 线为参考单位，预览与导出观感一致

## 5. 界面

```
┌──────────────┬──────────────────────────────────────┐
│  参数面板     │                                      │
│  ▸ 文案       │           实时预览画布                │
│  ▸ 光标       │        （按输出比例自适应）            │
│  ▸ 模板       │                                      │
│  ▸ 屏幕模拟   │                                      │
│  ▸ 镜头质感   ├──────────────────────────────────────┤
│  ▸ 输出       │ ▶ ━━━━━━●━━━━━━━  00:03.2 / 00:07.8  │
│  ▸ 速度       │           [下载当前帧] [导出 MP4]   │
└──────────────┴──────────────────────────────────────┘
```

- 参数改动即时反映到预览
- 播放 / 暂停 / 循环 / 拖动进度条逐帧查看
- 导出时显示进度条，可取消
- 下载当前帧：以输出分辨率保存进度条所在位置的画面（PNG，含屏幕模拟与镜头质感效果）；点击时自动暂停，预览停在所保存的那一帧
- 当前参数自动保存在浏览器本地；支持导出/导入参数 JSON，方便复用

## 6. 技术方案

### 6.1 技术栈
- **Vite + TypeScript + React**：工程与参数面板
- **Canvas 2D**：绘制 UI 场景（矢量绘制，镜头推到多近文字都清晰）
- **WebGL2**：后期特效（屏幕模拟、镜头质感）
- **WebCodecs `VideoEncoder` / `AudioEncoder`**：H.264 视频 + AAC 音频编码
- **Web Audio `OfflineAudioContext`**：按事件表离线合成完整音轨
- **Mediabunny**：封装 MP4
- **运行环境**：Chrome / Edge 最新版（WebCodecs 和 `Intl.Segmenter` 支持最完整）

### 6.2 核心原则：确定性渲染
整个动画是一个纯函数：`renderFrame(配置, 时间 t) → 一帧画面`。

- 预览：按真实时间调用
- 拖动进度条：任意 t 直接调用
- 导出：t = 0, 1/fps, 2/fps … 逐帧调用，渲染多慢都不会掉帧

### 6.3 模块划分

```
src/
  timeline/     文案切分、节奏模型 → 按键事件表 [{时刻, 已上屏文本, 焦点词范围}]
  camera/       根据事件表算焦点轨迹 → 弹簧模拟 → 每帧 {中心 x, y, 缩放}
  scene/
    templates/  各输入框模板：布局 + 绘制
    frames/     系统外框：macOS / Windows 浏览器窗口
    cursor.ts   光标形状与闪烁
  fx/           WebGL 后期链：屏幕模拟 → 景深 → 收尾（色差 / 暗角 / 颗粒），未开启的环节跳过
  audio/        按键音合成、按事件表生成音轨
  render.ts     renderFrame(config, t)：场景 → 镜头变换 → 后期
  export/       WebCodecs + Mediabunny 导出
  ui/           参数面板、播放控件
```

### 6.4 关键实现要点
- **字体**：渲染前等待 `document.fonts.ready`，确保首帧与导出一致
- **屏幕特效"长在屏幕上"**：着色器接收镜头变换参数，摩尔纹 / 像素网格定义在屏幕（场景）坐标系中，因此会随镜头推拉而正确缩放、流动
- **景深**：着色器接收焦点在画面中的位置，按距离做可变半径模糊
- **4K 导出**：H.264 需要 Level 5.1，导出前用 `VideoEncoder.isConfigSupported` 检测，不支持时给出提示
